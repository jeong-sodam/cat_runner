# Decisions: Mayhem 듀얼 입력·난이도 상향

- Date: 2026-09-22
- Status: Confirmed

## D01. 카오스 식별자와 서버 오류 처리
- **Chosen**: 내부 `catId`는 `chaos`로 유지하고 표시용 영문명만 `Mayhem`으로 변경한다. 서버 오류는 이름 변경으로 우회하지 않고 실제 요청 실패 원인을 수정한다.
- **Rationale**: 현재 서버는 `chaos`를 유효한 고양이 ID로 허용하므로 내부 ID 변경은 기존 데이터·자산·검증 계약의 불필요한 변경을 만든다.

## D02. 난이도 적용 범위
- **Chosen**: `home_day`, `outside`, `home_night` 전체 구간을 상향한다.
- **Rationale**: 초반부터 더 어려운 플레이를 원하지만 구간별 난이도 차이는 유지한다.

## D03. 장애물 밀도
- **Chosen**: 모든 기본 패턴에 장애물 1개를 추가하고, 모든 복합 패턴도 3개에서 4개로 확장한다.
- **Rationale**: 패턴 종류만 늘리는 것보다 실제 회피 판단 빈도를 높인다.

## D04. 이동 속도 난이도
- **Chosen**: 시작 속도를 10% 상향하고 거리 난이도 최대치를 기존 `1.5`에서 `1.65`로 올린다.
- **Rationale**: 초반 체감 난이도와 장거리 상승 폭을 함께 높이되 급격한 속도 폭증은 피한다.

## D05. 고난도 장애물 회피 여백
- **Chosen**: 일부 패턴은 연속 점프·슬라이드가 필요하도록 허용하고, 장애물 간 최소 안전 여백은 `120px`까지 줄인다. 실제 물리 시뮬레이션 테스트로 회피 가능성을 검증한다.
- **Rationale**: 200px 고정 여백보다 어려운 조합을 제공하되, 불가능한 패턴은 생성하지 않는다.

## D06. 복합 패턴 행동 시퀀스
- **Chosen**: 네 번째 장애물을 포함한 4단계 `jump`/`slide` 시퀀스를 seed 기반으로 무작위 생성하고, 클라이언트와 서버가 같은 결과를 생성해 parity 검증한다.
- **Rationale**: 패턴 반복을 줄이면서도 서버 authoritative 검증과 결정성을 유지한다.

## D07. 고양이 능력치 수
- **Chosen**: 기존 5종(점프, 속도, 슬라이드, 아이템 지속, 체력)에 자석 범위·점수 배율·낙사 저항·무적 지속시간을 더해 총 9종으로 확장한다.
- **Rationale**: 능력치 선택의 다양성을 높이되 화면과 밸런스가 관리 가능한 범위로 제한한다.

## D08. 능력치 표시와 등급
- **Chosen**: 선택 카드에 9종 능력치 막대를 모두 표시하고 1~5 등급을 사용한다. 3등급을 기준으로 등급마다 약 ±10%를 선형 적용한다.
- **Rationale**: 능력 차이를 한눈에 이해할 수 있고 수치 폭이 과도하게 벌어지지 않는다.

## D09. 고양이 역할 프리셋
- **Chosen**: 6마리 모두 고정 역할형 프리셋을 사용하며, 총합은 비슷하게 유지하고 고양이마다 강점 2개·약점 1개를 둔다. 구체 수치는 기존 콘셉트를 바탕으로 균형 설계한다.
- **Rationale**: 매 게임 무작위 능력치보다 캐릭터 선택의 의미와 학습 가능성을 보장한다.

## D10. 체력 규칙
- **Chosen**: 고양이별 체력 등급에 따라 최대 체력을 1등급 4칸, 3등급 5칸, 5등급 6칸으로 매핑한다. 장애물·낙사 피해는 1칸이다.
- **Rationale**: 기존 3하트보다 생존 단위를 명확하게 만들면서 체력 특화 고양이의 차이를 반영한다.

## D11. 듀얼 입력 구조
- **Chosen**: 왼손은 기존 키보드로 고양이를 조작하고, 오른손은 마우스로 osu 스타일 원형 타겟을 처리한다.
- **Rationale**: 달리기 조작과 별도 리듬 입력을 동시에 수행하는 새로운 플레이 루프를 만든다.

## D12. osu 타겟 생성과 난이도
- **Chosen**: 타겟은 브라우저에서 무작위 생성하고, 구간별 배율은 `home_day 1.0x → outside 1.5x → home_night 2.0x`로 적용한다. 구간이 올라갈수록 생성 빈도는 증가하고 타겟 크기는 감소한다.
- **Rationale**: seed 재현보다 즉각적인 리듬 플레이 변화를 우선하되, 구간별 난이도 체감은 일관되게 만든다.

## D13. 타겟 판정과 배치
- **Chosen**: 기존 Canvas에 통합 렌더링하며, 화면 전체에서 무작위 위치에 타겟을 표시한다. 다른 게임 요소와 겹칠 수 있지만 반투명하게 그리고 게임 충돌에는 영향을 주지 않는다. 타겟은 500ms 동안 표시된다.
- **Rationale**: 별도 DOM 레이어 없이 기존 논리 좌표계와 렌더 루프를 활용한다.

## D14. 동시 타겟 수
- **Chosen**: `home_day 1개 → outside 2개 → home_night 3개`를 동시에 표시하고, 각 타겟은 독립적으로 500ms 후 실패 처리한다.
- **Rationale**: 구간 난이도를 시각적 처리량으로 표현하면서 타겟별 판정을 명확히 한다.

## D15. 마우스 버튼과 보너스 타겟
- **Chosen**: 좌클릭은 일반 타겟, 우클릭은 보너스 타겟으로 사용한다. 보너스 타겟은 전체의 약 20%이며 성공 시 고정 +5점을 준다. 놓치면 일반 타겟 실패와 동일하게 정확도에 반영한다.
- **Rationale**: 오른손 입력을 단순 클릭 이상으로 확장하되, 보너스 타겟이 생존을 직접 좌우하지 않도록 한다.

## D16. osu 점수 반영과 서버 검증
- **Chosen**: 정확도는 성공·실패 2단계로 계산하고 최종 점수 배율 `0.8x~1.2x`에만 반영한다. 최종 정확도는 `run_gameover` payload로 전송하고, 서버는 범위와 배율만 검증한다.
- **Rationale**: 클라이언트 무작위 타겟을 서버가 재현하지 않는 구조의 한계를 인정하면서도 배율 조작 범위를 제한한다.

## D17. 서버 연결과 로컬 전환
- **Chosen**: 서버 연결이 확인될 때까지 게임 시작을 보류한다. 실패 시 사용자가 직접 선택할 때만 로컬 플레이로 전환하며, 로컬 결과는 서버 랭킹에 저장하지 않고 기기 내 최고 기록만 저장한다. 로컬 모드에는 `로컬 플레이 — 서버 랭킹에 저장되지 않음` 배지를 표시한다.
- **Rationale**: 정상 플레이의 서버 기록 신뢰도를 유지하면서 연결 장애에서도 사용자가 플레이를 선택할 수 있게 한다.

## D18. 연결 오류 안내와 로깅
- **Chosen**: 사용자에게는 안전한 안내문과 재시도·로컬 플레이 선택지를 보여주고, 개발 로그에는 HTTP 상태와 서버 오류 코드를 기록한다.
- **Rationale**: 내부 정보 노출을 막으면서 카오스 선택 시 실제 실패 원인을 추적할 수 있게 한다.
