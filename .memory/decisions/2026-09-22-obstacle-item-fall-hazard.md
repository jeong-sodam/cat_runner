# Decisions: 장애물·아이템 이미지 개선 및 낙사 위험

- Date: 2026-09-22
- Status: Confirmed

## D01. 오브젝트 이미지 에셋 구성

- **Chosen**: 투명 배경 PNG 6개를 독립 에셋으로 추가한다: `box`, `fence`, `pot`, `yarn`, `mouse`, `cat-grass`.
- **Rationale**: 현재 렌더러의 `getItemSprite(type, variant)` 구조와 자연스럽게 맞고, 변형별 시각 품질을 독립적으로 관리할 수 있다.

## D02. 이미지 스타일과 애니메이션

- **Chosen**: 기존 고양이·배경과 같은 따뜻한 동화책풍, 굵은 외곽선과 부드러운 그림자의 2배 해상도 투명 PNG를 사용한다. 이미지는 정적이며 캔버스에서 작은 흔들림·밝기 변화만 추가한다.
- **Rationale**: 새 에셋의 시각적 일관성을 유지하면서 프리로드 구조와 파일 용량을 단순하게 보존한다.

## D03. 기존 게임플레이 크기 보존

- **Chosen**: PNG의 논리 렌더링 크기, 쥐 인형·강아지풀의 수집 범위, 기존 엔티티 타입은 유지한다. 장애물만 별도 피격범위로 조정한다.
- **Rationale**: 이미지 개선이 수집 난이도나 패턴의 의도치 않은 변화로 이어지지 않게 한다.

## D04. 장애물 피격범위

- **Chosen**: 장애물 변형별 다각형 충돌을 적용한다. 화분·울타리·실뭉치·상자의 실제 실루엣을 따라가며, 시각 그림자 영역은 충돌에서 제외한다.
- **Rationale**: 단일 사각형 충돌보다 가장자리 오판정을 줄이면서 픽셀 단위 충돌보다 성능과 구현 복잡도를 관리할 수 있다.

## D05. 낙사 구간 생성

- **Chosen**: 바닥이 실제로 끊긴 어두운 구멍을 생성하며, 폭은 140~220px로 제한한다. `outside` 패턴의 약 15%, `home_night` 패턴의 약 30%에 생성하고 `home_day`에는 생성하지 않는다. 구멍 앞뒤에는 최소 200px 여유를 두며 구멍 위에는 장애물을 배치하지 않는다.
- **Rationale**: 일반 점프 한 번으로 넘을 수 있는 학습 가능한 위험을 초반 이후에 점진적으로 도입한다.

## D06. 낙사 처리와 복귀

- **Chosen**: 구멍에 빠지면 중력으로 잠깐 낙하하고 체력 10을 잃는다. 구멍을 빠져나온 직후의 바닥 위치에 복귀하며 진행 방향과 월드 진행은 유지한다. 복귀 후 1초 동안 무적이다. 기존 무적 효과가 활성화되어 있으면 낙사 피해는 막지만 낙하·복귀 연출과 이벤트는 발생한다.
- **Rationale**: 즉시 게임오버보다 실수를 회복할 기회를 주되, 현재 장애물 피해 규칙과 같은 피해량으로 위험도를 일관되게 유지한다.

## D07. 낙사 이벤트와 서버 이벤트 검증

- **Chosen**: `fall_damage` 이벤트를 추가하고 payload에는 `gapId`만 포함한다. 클라이언트·서버 패턴 매니페스트에 동일한 낙사 정의를 넣어 같은 시드에서 위치와 ID를 재현한다. 서버는 gap 존재 여부, 중복, 이벤트 순서를 검증하고 피해량 10을 적용한다.
- **Rationale**: 클라이언트가 피해량이나 임의 위치를 직접 보내지 못하게 하면서 기존 서버 이벤트 재생 구조를 유지한다. 전체 물리 재생 없이 실제 낙하 순간까지 검증하는 것은 이번 범위에서 제외한다.

## D08. 폴백과 기존 규칙 보존

- **Chosen**: PNG가 없거나 로드에 실패하면 기존 캔버스 벡터 드로잉을 사용한다. 조작 키, 사운드, 점수 계산, 수집 로직, 기존 엔티티 타입은 변경하지 않는다.
- **Rationale**: 에셋 장애가 플레이 불가로 이어지지 않게 하고 이번 기능의 범위를 시각 개선·피격범위·낙사 위험으로 제한한다.
