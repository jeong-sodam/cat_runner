# Plan: Mouse Cleanup and Stage Score Thresholds

## Goal

Reorganize ordinary route mice into a continuous, single-row collectible path without changing special 5x5 formations or collectible density. Ordinary mice must use deterministic `48~58px` spacing at `y=610`, skip only positions that collide with obstacles, continue through fall gaps and pattern bridges, and remain client/server identical. Move stage transitions to `800` and `3600` score while leaving mouse, distance, and osu/rhythm score awards unchanged.

## Global Constraints

- Only ordinary mice (`type: "mouse"` without `formationId`) are reorganized. Heart, star, clover, thumbs-up, alphabet, and DEX formations keep their existing cells, shape metadata, and cell counts.
- Ordinary route candidates use the fixed row `GAME_CONFIG.groundY - 90`, which is `610` with the current `groundY: 700`.
- `GAME_CONFIG.mouseRouteSpacingMin` and `mouseRouteSpacingMax` become `48` and `58`. `routeSpacing` is selected from this inclusive range through the existing seeded random stream, not through `Math.random()`.
- An ordinary candidate that AABB-overlaps an obstacle is omitted. The next candidate resumes from the next seeded spacing position. Fall gaps continue to receive the fixed-row route with airborne gap validation.
- Pattern-boundary bridges continue to be generated by `world.js`/the server manifest using the same seeded `routeSpacing` and fixed row.
- Stage thresholds are `outside.minScore = 800` and `home_night.minScore = 3600`. These thresholds drive the actual zone, background, obstacle pattern eligibility, difficulty multiplier, and osu/rhythm zone configuration. Score award formulas remain unchanged.
- Client and server must use the same random-call order, spacing clamp, route metadata, pattern version, entity ordering, and y positions. Bump the pattern contract version from `v9` to `v10` because generated route data changes.
- Work is sequential through `.memory/current.md`; no implementation code is written during planning.
